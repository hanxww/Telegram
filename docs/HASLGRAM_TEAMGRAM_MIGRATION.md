# HaslGram — полностью независимый Telegram-подобный мессенджер

**Требование владельца:** один собственный сервер (под его управлением) и собственное приложение **HaslGram**. Никаких пользователей, чатов, групп или каналов из Telegram и чужих серверов. Устанавливается **пустая база данных**; новые пользователи появляются исключительно при регистрации в HaslGram. Никакой обязательной интеграции с официальным Telegram и его Bot API.

**Статус на 2026-11-08:** архитектура подтверждена; сервер Teamgram на VPS **не развёрнут**, изменённый Android-клиент **не собран**, подарки и собственный код входа в MTProto **не реализованы**. Рабочая сборка исходного Telegram сохранена в `master` и не затронута.

## Базовая архитектура: одна независимая сеть

```text
HaslGram Android (модифицированный Teamgram Android)
              │
              │ MTProto 2.0 (только наш IP/domain, без fallback на Telegram/Teamgram)
              ▼
     HaslGram MTProto Gateway (gnetway TCP 10443)
              │
              ▼
     Наш Teamgram Server (Go, self-hosted, собственные ключи)
              │
              ├─ MySQL (новая БД HaslGram: пользователи, чаты, сообщения)
              ├─ Redis (сессии)
              ├─ etcd (discovery)
              ├─ Kafka (события)
              ├─ MinIO (файлы)
              └─ Модуль подарков/Stars (добавить на стороне нашего сервера)
```

Важное различие: речь не о «взломе» Telegram, а о законном форке открытого клиента и развёртывании сторонней реализации совместимого серверного протокола. Оригинальный Telegram не имеет публично доступного полного серверного исходного кода, поэтому используем Teamgram Server.

## Требования к HaslGram

- База на старте пустая; не импортировать пользователей, группы, чаты, контакты и каналы.
- Сервер и регистрация только свои; никакого обращения к официальной сети Telegram или к чужим дата-центрам Teamgram.
- Подключения Android только к собственному MTProto gateway. Проверить не только `ConnectionsManager.cpp`, но и адреса-заглушки, тестовые/продовые DC, DNS, CDN, feature fallback и обработку смены DC. Верифицировать сетевыми логами.
- Переименовать приложение, `applicationId`, UI и значки в HaslGram; заменить все ключи подписи и сторонние учётные данные.
- Собственный безопасный механизм выдачи одноразовых кодов через HaslGram Server (например, дополнительная регистрация по приглашению + второй фактор). **Не** использовать тестовый код Teamgram `12345` и **не** выдавать код через обычное уведомление неаутентифицированного HaslGram.
- Не привязывать обязательную регистрацию к `@HaslGramRegBot`: это бот в *официальной сети Telegram* и нарушает требование полной независимости. Старую разработку не удаляем, но не включаем её в новую схему.
- Убрать из UI создание групп, каналы и иные ненужные функции; запретить соответствующие серверные операции, если они реализованы. Просто скрыть кнопки недостаточно, если нужен строгий запрет.
- На старте использовать личные чаты, профиль, контакты, загрузку медиа; проверять каждую возможность на тестовых устройствах.
- Подарки и Stars: новые структуры данных и транзакционная логика **внутри** HaslGram backend, расширение MTProto/API и UI. Нельзя считать их работающими только потому, что в старом NestJS имеются отдельные API.
- Перед публикацией проверить лицензию Android-кода (GPL), лицензию Teamgram Server (Apache-2.0), хранение персональных данных, защиту от перебора кодов и аудиты ключей.

## Реальное состояние Teamgram

- https://github.com/teamgram/teamgram-server — сервер MTProto 2.0; Community Edition поддерживает личные сообщения, контакты и базовые группы, но не гарантирует все возможности Telegram.
- https://github.com/teamgram/teamgram-android/tree/teamgram2 — соответствующий клиент; нужно адаптировать под сервер HaslGram, затем собрать отдельно от `master`.
- https://github.com/teamgram/teamgram-server/blob/master/specs/architecture.md — сетевые порты и топология.
- Документированный Docker-путь: клонировать сервер; `docker compose -f docker-compose-env.yaml up -d` для зависимостей, `docker compose up -d` для приложения. Запускать в отдельном каталоге и с отдельным Docker Compose project, а не поверх работающего старого проекта.
- Тестовый вход по коду `12345` по умолчанию **небезопасен для публичного сервера**; обязательно заменить до открытия регистрации.

## Этапы и критерии готовности

1. Проверить занятые порты, бэкапы, конфигурации Docker и внешние ограничения VPS.
2. Развернуть свой Teamgram Server **с новой базой** и секретами в отдельном окружении; ограничить доступ до устранения тестовой авторизации.
3. Реализовать безопасную собственную регистрацию на сервере.
4. Создать Android fork и направить все MTProto-соединения только к HaslGram, без fallback; заменить брендирование и signing.
5. Проверить два независимых аккаунта и отправку/получение сообщений, перезапуск сервера и сохранность данных.
6. Реализовать Stars и подарки на том же собственном сервере и в Android, с защитой от дублей покупок и отрицательных балансов.
7. Собрать подписанный HaslGram APK через GitHub Actions, проверить на телефоне и только затем обозначить как релиз.

## Существующий проект

Старый `/opt/haslgram/haslgram-gift-engine` (NestJS, PostgreSQL, Redis, Telegram-бот) **не удалять**, не менять его данные и тома без подтверждённой миграции. Он не нужен для независимой MTProto-сети. Если позднее понадобится перенести ранее выданные Stars/подарки, отдельно проектируем безопасную миграцию, но **не привязываем сервисы для работы основных функций**.
