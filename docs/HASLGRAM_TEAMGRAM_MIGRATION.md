# HaslGram — окончательные требования к независимому мессенджеру

**Статус:** техническое задание владельца и анализ осуществимости. Ни полный клиент, ни серверная функциональность из этого документа пока не реализованы и не протестированы. Ветка: `haslgram-teamgram`; существующая рабочая ветка `master` не затрагивается.

## 1. Цель

Самостоятельная сеть **HaslGram** на собственном сервере, с собственной, изначально пустой базой пользователей, чатов, групп и каналов. Приложение Android должно иметь привычный интерфейс официального Telegram и, **по требованию владельца, сохранять весь его набор возможностей** (см. ограничения ниже).

Новые данные не должны браться из аккаунтов официальной сети Telegram; сообщения, медиа, пользовательские профили и групповые данные должны храниться в HaslGram. Нельзя выдавать недоступные функции Teamgram за готовые.

## 2. Регистрация и вход: только через @HaslGramRegBot

- Регистрация/новая сессия HaslGram разрешается только по коду от `@HaslGramRegBot`, который работает **в официальном Telegram**.
- Пользователь открывает бота, нажимает «Поделиться моим номером» стандартной кнопкой `request_contact`.
- Проверять `contact.user_id === message.from.id`, чтобы нельзя было зарегистрироваться по чужому контакту; телефон нормализуется в E.164.
- Бот и сервер выдают одноразовый криптографически случайный код с коротким TTL. Сервер хранит только хеш кода, ограничивает попытки, частоту выдачи и блокирует повторное использование.
- MTProto `auth.sendCode` / `auth.signIn` должны использовать **реальную серверную проверку** кода бота. Старый фиксированный Teamgram тестовый код `12345` запрещён.
- Идентификатор аккаунта HaslGram должен быть стабильным и однозначно связан с `telegramUserId` и проверенным номером. Нельзя доверять `telegramUserId`, переданному клиентом без подтверждения на стороне бота.
- **Только при первой успешной регистрации** начислить **2 000 Hasl Stars** атомарной транзакцией, идемпотентно (однократность), с учётом блокировки повторных бонусов на тот же Telegram ID/номер.
- Важная граница независимости: **сеть сообщений остаётся нашей**, но для создания аккаунта пользователю всё ещё потребуется официальный Telegram, чтобы воспользоваться ботом. Это осознанное требование владельца.

## 3. Полный функционал Telegram — требование

Сохранять и реализовывать:
- личные и групповые чаты, супергруппы, каналы;
- сообщения, ответы, пересылку, закрепление, редактирование, удаление, истории;
- фото, видео, документы, аудио, голосовые, видеосообщения и поиск;
- реакции, стикеры, темы, анимированные и пользовательские emoji;
- звонки, групповые звонки/эфиры (если ожидается эквивалент официального Telegram);
- боты и мини-приложения внутри сети HaslGram;
- multi-device, push, секретные чаты и 2FA, настройки приватности;
- Premium-права и ограничения как серверные функции, не только значок в UI.

**Фактическое ограничение:** Community-версия `teamgram/teamgram-server` публикует только частный чат, базовую группу, контакты и web как core features; каналы/супергруппы, звонки, боты, miniapp, secret chat, push и прочее указаны как enterprise. Простое подключение официального Android-клиента к Teamgram Community **не** даёт 100% функционал. Возможные пути: приобрести лицензируемую Enterprise-версию и дописать отсутствующее либо самостоятельно реализовать требуемый серверный API и сервисы. Нельзя копировать закрытый сервер Telegram.

Источник: https://github.com/teamgram/teamgram-server

## 4. Экономика: свои Hasl Stars и HaslGram Premium

- Hasl Stars — **внутренняя валюта HaslGram**, не Telegram Stars, не может автоматически учитываться или тратиться в официальной сети Telegram.
- Цены на покупку Stars устанавливает HaslGram; платежи должны обрабатываться через разрешённый платёжный провайдер с учётом правил платформы и законов.
- HaslGram Premium — своя подписка и серверные права; **не** выдаёт официальный Telegram Premium.
- Бонус новым аккаунтам 2 000 Stars начисляется **один раз**, нужен журнал операций, защита от повторной регистрации и злоупотреблений.

## 5. Подарки — требуемая бизнес-логика

1. Каталог подарков — обычные варианты из Telegram, в том числе ранее выпущенные.
2. **Цена обычного подарка** должна соответствовать **цене на момент первоначального появления** в официальном Telegram, а не текущей перепродажной цене и не стоимости коллекционного варианта.
3. Покупка обычного подарка за Hasl Stars с учётом остатков и атомарного списания.
4. После получения владелец может **доплатить за улучшение** подарка до коллекционного.
5. Для коллекционных подарков нужны **оригинальные модели, узоры, фоны и вероятности**, а также номера, редкости, атрибуты; случайный выбор выполняет сервер, не Android.
6. Показывать коллекцию в профиле, владение, передачу, дальнейшие операции — по мере реализации соответствующих серверных методов; не имитировать выполненные транзакции интерфейсом.
7. Защита от двойных списаний, подмены цен, повторных улучшений и нарушения остатков обязательна.

**Данные и права:** официальный API документирует `payments.getStarGifts`, `payments.getStarGiftUpgradePreview`, `payments.getStarGiftUpgradeAttributes`, `starGiftAttributeModel`, `starGiftAttributePattern`, `starGiftAttributeBackdrop`. Но официальный сервер владеет данными и файлами/документами, а не Teamgram. Для самостоятельного сервера нужен **законно полученный собственный снимок каталога и медиаресурсов** и собственное хранение/выдача. Историческую первоначальную цену для каждого подарка необходимо **верифицировать отдельно**; API не гарантирует историческую цену выпуска для всех подарков. Не заявлять полное наполнение каталога без такой проверки.

Источники:
- https://core.telegram.org/api/gifts
- https://core.telegram.org/type/StarGiftAttribute

## 6. Сетевая архитектура

```text
HaslGram Android (открытый Telegram/Teamgram fork с собственным брендом)
     │
     ├── MTProto 2.0 ─► HaslGram self-hosted MTProto server (Teamgram fork)
     │                        ├── Users / chats / channels / groups / files
     │                        ├── Custom auth service ← verified bot codes
     │                        └── Hasl Stars, Premium and gifts services
     │
     └── Optional HTTPS API ─► HaslGram backend if technically justified

@HaslGramRegBot (official Telegram) ─► HaslGram registration service
                                      (only external registration transport)
```

- Все MTProto-соединения из Android **только** на наш MTProto gateway; удалить fallback на Telegram/чужой Teamgram.
- Мобильные пользователи и чаты всегда хранятся в нашей новой базе. На старте нет чужих каналов/чатов/пользователей. Возможность создания групп и каналов **сохраняется**.
- Существующий `/opt/haslgram/haslgram-gift-engine` (NestJS, PostgreSQL, Redis, бот) уже работает, его данные не удалять. Можно использовать его модуль регистрации/экономики, но серверное сопоставление и безопасность сессий должны быть реализованы полностью.
- Teamgram требует отдельной инфраструктуры (MySQL, Redis, etcd, Kafka, MinIO и прочее) и собственного резервного копирования; это по-прежнему **наш сервер**, даже если на нём много внутренних процессов.
- Изменить package ID, иконки, строки, ключ подписи, FCM/Google API ключи; соблюсти лицензии GPL-2.0 и Apache-2.0. Не распространять «финальную» сборку с тестовыми секретами.
